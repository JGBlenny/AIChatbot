# 多輪對話煙囪劇本（手動測試用）

> 2026-07-07 整理。適用：8087 chat-test 頁或直打 `/api/v1/message`。
> 身分設定：vendor 2、`mode=b2b`、`target_user=property_manager`、`role_id=37305`（有真資料的測試角色）。
> **同一組劇本必須用同一個 session_id 連續送**；session 前綴避開內部保留字（backtest_/loop_/smoke_ 等）。
> 單句煙囪（20 面向各一句）見 `docs/deployment-runbook.md` §5。

## ① 帳單診斷（無編號→物件名→候選→決定性判定）

```
你：帳單為什麼一直發不出去
　→ 預期：問你要帳單編號或物件名稱
你：我沒有編號，可以用物件名稱查嗎
　→ 預期：說可以，請你給物件名稱
你：台北大同-重慶北137-503
　→ 預期：列出帳單候選（最多 8 筆，含日期/金額），請你回序號
你：2
　→ 預期：該帳單的決定性診斷——現況狀態＋可否發送/取消/手動到帳＋原因
```

已知輪次浪費（引擎既有債，非部署問題）：若第 1 輪已講症狀、第 2 輪直接給物件名，
會再被問一次症狀——回一次症狀即繼續。

## ② 合約診斷（識別鏈＋按現值判定）

```
你：合約為什麼不能點交
　→ 預期：要合約編號或物件名稱
你：台北大同-重慶北137-503
　→ 預期：同名多筆列候選要你選
你：1
　→ 預期：按該合約現況答可否點交與條件
```

## ③ 合約異動（分流型追問）

```
你：我想改合約 內容要修改
　→ 預期：問要改哪一項（租期/租金/承租人…）
你：想把租期延長
　→ 預期：往續約/異動方向引導，要合約識別
你：重慶北137-503
　→ 預期：按該約現況給異動出口（複製重簽 vs 資料異動申請＋藍字風險提醒）
```

## ④ 繳費金流排障（skip_refine 候選直列）

```
你：租客說錢繳了 可是帳一直沒進來
　→ 預期：要帳單編號或合約/物件名
你：台北大同-重慶北137-503
　→ 預期：直接列該合約帳單候選（不得再要求「補更明確識別」）
你：1
　→ 預期：按金流階段判定（待對帳/超商撥付時程/查無繳費核對引導）
```

## ⑤ 電表排障

```
你：電表一直離線 度數不動
　→ 預期：要物件/房號/電表名
你：新北新莊-富貴500-14B05
　→ 預期：按電表現值判因（離線/正常/儲值狀態），不代操作
```

## ⑥ 退租收尾（多步驟引導）

```
你：租客要退租了 接下來我要做什麼
　→ 預期：問到期退租還是提前解約
你：提前解約
　→ 預期：講租客/房東發起差異與 7 天回應期，往申請流程引導
你：租客發起的話違約金怎麼算
　→ 預期：預告期比對邏輯（60 天門檻、兩組違約金）＋系統會自動算
```

## 橫切觀察點（任一劇本內可加測）

- **中途切題**：在②第 2 輪突然問「電表怎麼儲值」→ 應切面向不硬答
- **亂給編號**：「999999」→ 誠實查無回追問，不得瞎編
- **對照組（不得誤進對話）**：「點退押金的找補費用在哪裡操作」「帳單可以批次匯入嗎 怎麼操作」→ 單發直答

## 測後清理

手測事件會記入使用量統計（若 session 前綴不在內部清單即算真流量），測完清理：

```sql
DELETE FROM usage_events WHERE session_id LIKE 'web_manual_%';  -- 換成你用的前綴
```
