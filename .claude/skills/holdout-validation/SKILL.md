# 凍結留出驗證（deterministic holdout validation）

## 這支 skill 存在的理由

實測教訓（2026-08，本專案）：**先跑系統、再決定怎麼判，等於沒驗。**
人（與模型）會在看到結果後不自覺地調整判準，讓任何結果都變成 PASS。
更糟的是**量尺自己是瞎的**——用一把看不見病灶的尺量出「沒問題」，
結論的破壞力比量錯還大。

⛔ 這支 skill 不是通用測試流程。它專門對付「判定型系統」——
輸出是分類／路由／進場與否，而非確定值。

## 鐵則（違反任何一條，該輪作廢）

```text
① 順序不可逆：凍結判準 → 造語料 → 標註 → **才**跑系統
   ⛔ 看過系統輸出之後不得修改 label definition、不得補題、不得改題
② 量尺先自證：把已知病灶餵給量尺，它必須紅
   看不見已知病灶的尺，它的 PASS 不構成證據（同不變量 8/9 的 --self-test 紀律）
③ 造題與標註分離：兩個獨立代理，**都必須 0 tool calls**
   ⚠️ 用 harness 計數判定，⛔ 不採信代理自述「我沒有查」
④ 語料用完即焚：進過 KB／prompt／調參的語料不再是 holdout
   燒毀後的語料只能用於失敗分析，⛔ 不得再拿來宣稱率
⑤ 合成就說合成：合成語料的覆蓋率**不得**外推成 production 覆蓋率
⑥ 否定結論要有正對照：宣稱「找不到／沒有／不存在」之前，
   檢查清單裡必須含一個已知必然存在的項目；它若也沒中＝工具壞了
```

## 執行協議

### 第 0 步：把宣稱寫成可否證的一句話

```text
✅「instance gate 對無實例參照的 query 會抑制 Face 進場」
❌「路由品質改善了」          ← 不可否證
❌「準確率提高且延遲下降」    ← 兩個宣稱，拆開
```

同時寫下 **claim ceiling**：這輪**不能**宣稱什麼。先寫，別事後補。

### 第 1 步：凍結協議（`--dry-run` 就停在這）

在**任何語料存在之前**寫下並落檔：

```text
・母體定義與分層（strata），每層的預期筆數
・label 定義（每個標籤的判準、邊界案例怎麼歸）
・通過門檻（多少算 PASS）——⛔ 事後不得調整
・coverage precondition：哪一層筆數不足時整輪 INCONCLUSIVE
・n 的紀律：`n<30` 套到**交叉表的每一格**，不只總 N
   例：總 N=5000 不代表「category=電表、N=8」那格可以宣稱率
・withheld list：哪些資訊不給造題者、不給標註者
```

### 第 2 步：造題（隔離代理，0 tool calls）

派一個代理，只給 strata 定義與題數，**不給**：系統實作、既有失敗案例、
label 定義、通過門檻。⚠️ 造題者知道判準就會寫出剛好落在判準上的題目。

### 第 3 步：標註（另一個隔離代理，0 tool calls）

只給 label 定義與題目，**不給**系統輸出。標註完成後 **label 立即凍結**。

```text
⛔ 標註回來後不得修改 label definition——那等於用答案改考卷
```

### 第 4 步：量尺自證（跑系統**之前**）

```text
・正控制：植入一個已知違規／已知病灶 → 量尺必須紅
・突變控制：把已 PASS 的樣本改壞一個關鍵屬性 → 必須轉紅
            把已 FAIL 的樣本補上該屬性 → 必須轉綠
  （這一組證明它讀的是**屬性**，不是樣本 id 或表面特徵）
・若量尺是換新的：先驗新尺看得見舊尺抓到的病灶，再換
```

### 第 5 步：跑系統，一次

```text
・環境先驗一致性（容器 image 是否含待測程式碼——本專案有不變量 3）
・非決定性成分要標明：若判定鏈含 LLM，同輸入多跑幾次看散度
  ⚠️ 本專案實測：同一份程式碼三次跑出 7/6/5 紅 ⇒ 該套件**不是**決定性回歸量尺
・逐格記錄，不只總數
```

### 第 6 步：判定與登債

```text
PASS／FAIL／**INCONCLUSIVE** 三態，⛔ 不得把 INCONCLUSIVE 寫成 PASS
INCONCLUSIVE 必須說出**缺什麼證據**才能定案（而不是「再跑一次看看」）
未被走到的分支 → **NOT EXERCISED**，不是 PARTIAL FAIL
   ⛔ 不得為了讓分支進去而修改 production 資料
```

## 常見的假綠（本專案實際踩過）

```text
・設定宣告了端點，但 consumer 靠別的機制分派 ⇒ 能力仍不可達
・測試「跑了」但被 marker deselect ⇒ passed=0 卻顯示綠
・失敗注入被 helper 覆蓋掉 ⇒ 注入的例外根本沒到達待測碼
・容器是舊 image ⇒ 整輪結論與待測程式碼無關
・判定單位錯層：用 category 層事實推 row 層結論（或反之）
・checker 只讀設定的一種形狀（`secondary_call`），設定改成另一種
  （`secondary_calls`）後憑空多報
```

## 輸出格式

```markdown
## 宣稱
<一句話>

## Claim ceiling
⛔ 本輪不得宣稱：<列表>

## 凍結協議
<strata／label 定義／門檻／coverage precondition／withheld list>

## 量尺自證
正控制：<病灶> → <紅/綠>
突變控制：<改動> → <必須轉紅/綠>

## 結果
<逐格表；每格附 n；n<30 的格子只報 observed 不報率>

## 判定
PASS / FAIL / INCONCLUSIVE（缺 <什麼證據>）
NOT EXERCISED：<未走到的分支>

## 登債
<不擋收案但要記的殘留，逐條命名>
```
