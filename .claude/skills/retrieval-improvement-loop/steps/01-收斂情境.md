# 第 1 步：收斂情境（凍結）

> 流程全圖、鐵律與閘門見 [`../SKILL.md`](../SKILL.md)。**⛔ 本檔只放這一塊。**

## 順序不可逆

```text
寫死選題規則 → 抽樣 → 命中提名 → **業主確認** → 凍結 sha256 → 才准跑量測
⛔ 看過任何檢索輸出之後，不得改規則、不得補題、不得換題
```

## 選題規則要寫死的五件事

```text
① 母體      精確到可重跑的查詢條件；抽樣前先 assert 筆數，對不上就**大聲失敗**
② 分層與配額 依真實流量的維度分層（角色／模式），最大餘數法補齊
③ 排除條款  ⛔ **只能依型別與資料有效性**：
              非問句（純數字／測試字樣／無語義）
              不同題型（要求某筆記錄現值的、片段追問的）
            ⛔ 不得依長度、難易、或**任何檢索結果**排除
④ 排序      決定性：`md5(SEED || ':' || id)` 升冪，被排除者順延
⑤ SEED      寫進凍結檔
```

## 規則改版的紀律

```text
可以改：**尚未跑過任何量測**時
怎麼改：新開一版 → 註明原因 → **同 SEED 重抽** → 舊版抽樣結果保留可覆核
⛔ 不得就地改：改完沒人分得出「這批是不是挑過的」
```

⚠️ 實例：本專案的 T1 選題規則從 v1 改到 v3（業主改批量、補非問句排除、放寬 T2 偵測），
三次都在抽樣或跑測之前，v2 的完整抽樣保留在 `t1-draw-v2-superseded.json`。

## 命中提名：提名 ≠ 判定

```text
提名法  詞面重疊（字元 n-gram）或其他**與被驗系統不同源**的方法
⛔ 禁用  被驗系統自己的排序（向量＋reranker）
        ——業主一順著點頭，尺就與系統同構，及格線又回到被驗方手上
規約    每題至多 5 筆候選，附各筆 answer 全文供判讀
決定權  **業主**。⛔ 標註不得由實作方單獨完成
```

⚠️ **「以上皆非」是合法且有價值的答案**＝知識缺口，正是要治的東西，
⛔ 不得為了湊滿題數勉強指定一筆。若 NO_COVERAGE 過多導致湊不滿，**照實報數，⛔ 不遞補**。

## 出口

```text
規則檔（凍結，含 SEED 與排除條款）
抽樣檔（sha256）
命中確認紀錄（誰、何時、逐題 confirmed 或 NO_COVERAGE）
```
