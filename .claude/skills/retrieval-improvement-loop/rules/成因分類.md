# 成因六類：分錯類，優化就白做

> 流程全圖、鐵律與閘門見 [`../SKILL.md`](../SKILL.md)。**⛔ 本檔只放這一塊。**

## 六類與各自的修法

| 類 | 判準 | 修法 | ⛔ 不是 |
|---|---|---|---|
| **I 管線／索引** | 量測或檢索基礎設施本身壞了 | 修索引／參數／容器／DDL | ⛔ 不是改知識 |
| **V 可見性** | 語義最相關那筆被 `business_types`／`target_user`／`vendor_ids` 濾掉 | 改**資料歸屬** | ⛔ 不是改檢索、⛔ 不是補知識 |
| **T 門檻** | 可見，但融合分數沒過門檻 | 調門檻（⚠️ 需基準） | ⛔ 不是補知識 |
| **R 排序** | 正解有回但名次落後 | 精排／權重 | ⛔ 不是補知識 |
| **S 表示法** | 語義 top1 本身不對題 | 知識寫法／`retrieval_representation` | |
| **N 知識缺口** | 精確掃描前 15 筆全不對題 | 寫新知識 | |

## 判定順序（⛔ 不可跳）

```text
1. 先確認沒有 I —— **I 類存在時其他分類全部不可信**
2. 再看語義 top1（用**精確掃描**，⛔ 不用 ANN 結果）對不對題
   不對題 → S 或 N（看前 15 筆有沒有對的）
   對題   → 再看它可不可見
              不可見 → V
              可見   → 看分數與名次 → T 或 R
```

## ⛔ 本專案已四次分錯類

```text
把 I 誤判成 S    索引丟答案 → 以為是「知識寫得不好」→ 差點去改一堆沒問題的知識
把 V 誤判成 N    知識在另一個池 → 以為庫裡沒有 → 差點去寫一篇早就存在的知識
```

⇒ **每一次的修法都是白工**，而且會在錯誤的方向上累積工時與信心。

## V 類的特別警告

過濾器本身**可能是刻意的隔離機制**。動之前先查前案：

```text
docs/retrieval-recall-audit-20260822.md:82
  b2b 的 `business_types && {system_provider}` 嚴格過濾是刻意的，⛔ 勿改
```
⇒ V 類的修法是**改那筆資料的歸屬**，⛔ 不是放寬過濾器。
放寬過濾器會打穿隔離，且症狀要很久以後才看得到。
