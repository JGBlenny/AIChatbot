# 測哪一層：⛔ 元件層不得用來宣稱療效

> 流程全圖、鐵律與閘門見 [`../SKILL.md`](../SKILL.md)。**⛔ 本檔只放這一塊。**
>
> ⚠️ 這是 2026-09-01 業主連續三次糾正才長出來的規則。三次的話原封記在下方。

## 鐵律

> **要驗的是「完整的正式系統 ＋ 這一刀優化」，⛔ 不是元件。**

```text
✅ 療效驗收唯一合法的層  正式入口 POST /api/v1/message
                        （mode／target_user／role_id／vendor_id 依契約 §1 帶齊）
⚠️ 元件層（retrieve_knowledge_hybrid 等）  **只能用於第 4 步成因盤查**
⛔ 元件層 ⛔ 不得用來宣稱「改善了什麼」
⛔ 自己手寫的 SQL ⛔ 一律不得作為任何結論的依據
```

## 為什麼（三次糾正，逐條）

### ① 「你拿自己想的檢索去測試？」
2026-09-01 我手寫了一份診斷 SQL，量出「top-20 召回率 31%」並宣稱那是生產檢索的召回率。
實際上生產的 `ORDER BY (1 - (embedding <=> v)) DESC` **用不到向量索引**（算式＋DESC），
一律走精確掃描；我的 SQL 用正規寫法 `ORDER BY embedding <=> v` 才會走索引。

⇒ **我量到的是我的工具，不是系統。** 兩種寫法的召回率差 70%。

⚠️ 更難堪的是：`retrieve_knowledge_hybrid` **本來就有 `return_unfiltered=True` /
`return_debug_info=True`**，我要的中間狀態生產入口自己就給得出來。⛔ 完全沒必要自寫 SQL。

### ② 「不是要判斷正式的檢索加上優化能不能改善問題嗎？」
就算改用生產的檢索器，那也只是**元件**。使用者實際走的是
入口 → 意圖分類 → SOP 與知識仲裁 → 面向進場 → 答案合成。
檢索器回了對的知識，不代表使用者看得到那個答案——下游每一層都可能換掉它。

⇒ **療效必須在使用者看得到的那一層量。**

### ③ 「元件測試在製作規格時不是都測過了」
是。spec 階段的單元測試、整合測試與 25 條稽核不變量已經覆蓋元件層。
**再測一次元件不會產生新資訊**，只會消耗時間並製造「有在驗」的錯覺。

⇒ 這條迴圈要買的是**元件測試買不到的東西**：組起來之後使用者實際拿到什麼。

## e2e 實例：只有這一層看得到的東西

```text
ts9815「系統顯示『您尚未上傳合約檔案』，這是什麼意思？」
  元件層看到  檢索回 0 筆
  e2e 看到    「我目前沒有找到符合您問題的資訊…請撥打客服專線 02-8765-4321」
              action_type=direct_answer｜sources=[]｜confidence=0.0
⇒ 業者被打發去打電話。**這才是「問題」本身**，元件層量不到。
```

## 執行規約

```text
入口   POST /api/v1/message
       ⚠️ RAG_API_AUTH_ENFORCE=true ⇒ 未帶 X-API-Key 會 401（是認證擋下，⛔ 不是功能故障）
       ⚠️ 金鑰從 .env 自行讀取，⛔ 不經 argv、⛔ 不經 docker -e、⛔ 不印出
身分   依 docs/jgb2-chat-integration.md §1 的三種形狀，⛔ 不得自創組合
       ⚠️ 帶錯 mode 即受眾錯位——本專案已有一次立案後撤案的先例（harness 未帶 mode）
session ⛔ 前綴避開內部保留字（backtest_／loop_／smoke_）否則會被標成內部流量
非決定性 同 HEAD 重跑路由變異 13% ⇒ 每邊 ≥3 輪取變異；療效小於變異即雜訊
成本   每題全程呼叫 OpenAI ⇒ 跑之前先估並呈報
```

## 什麼時候可以只跑元件

```text
唯一情況：這一刀的**元件輸出逐筆相同**時，可省略 e2e（下游輸入相同 ⇒ 輸出不會變）
⚠️ 且必須明說是「因為輸出相同所以省略」，⛔ 不得寫成「已驗證無療效」
實例：索引 ivfflat→hnsw，35 題檢索輸出 top1 與分數逐筆相同 ⇒ e2e 只會量到 LLM 雜訊
```
