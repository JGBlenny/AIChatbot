# DSP-123：正式機對話模型沿用本機 Bedrock 長期金鑰

**日期**：2026-10-29　**決定者**：業主

**決定**：chatai 正式機（`docker-compose.bedrock-prod.yml` 的 secret `agent_llm_api_key`，主機路徑 `/home/ec2-user/.config/aichatbot/bedrock-api-key`）使用 DSP-090 那把本機長期金鑰（本機 `~/.config/aichatbot/bedrock-api-key`），⛔ 另開正式機專用金鑰。取代 DSP-090「本機長期金鑰 ⛔ 用於正式機」一句。

**業主原話**（2026-10-29）：「用原本那隻」。

**背景**：部署 c4603e13 時 `deploy.sh check` 顯示正式機沒有金鑰檔；紀錄中沒有正式機專用金鑰（DSP-121「金鑰 不管」後無人建立），業主沒有 AWS 權限、需請管理員另開。主會話列出三條路：請管理員另開（主會話建議）、先以 gpt-6-luna 部署、沿用本機金鑰（推翻 DSP-090）；業主選第三條。主會話提議先補推翻卡與反向攻擊，業主直接裁定，未做。

**已知代價（業主裁定前已告知）**：
- AWS 原文「Long-term keys are for exploration only」。
- 到期 ≤90 天（DSP-090），到期當天正式機對話中斷；實際到期日以 AWS console 為準（本線未查）。
- 本機與正式機共用同一把：任一端外洩或輪替，兩端同時中斷。輪替步驟同 DSP-090（console Deactivate → 兩端換檔 → `up -d --force-recreate`，正式機要帶 bedrock-prod 覆寫檔）。
