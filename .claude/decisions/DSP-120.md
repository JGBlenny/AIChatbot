# DSP-120

以下為 2026-10-28 建立時的原文與依據。

**決定**：照片與文件上傳列入站內幫手上線最低範圍。包含：
- JGB 端：面板支援照片與文件上傳，照接口 A §7 帶 `image_urls`／`file_urls`／`attachment_purpose` 呼叫 `agent.turn`（上線事項 L4，`jgb-spec-structured-card-draft-20261019.md` §2）；回覆接口 B #22 的照片交付方式與專用上傳網域。兩件都擋上線。
- AIChatbot 端（擋上線）：依 #22 定案改 `broken_photos` 送法（現行送物件陣列，jgb2 既有端點收網址字串陣列，會回 400）；把專用上傳網域加進 `IMAGE_URL_ALLOWLIST`。
- 不擋上線（主會話預設，業主 2026-10-28「沒這麼多檔上線」後收斂）：上線時照片辨識沿用現行 `IMAGE_RECOGNITION_MODEL`（OpenAI），DSP-111 切換排上線後（DSP-115）；上傳回合的品質量測記後補。

**業主原話**（2026-10-28 對話）：業主問「給 JGB 的規格有包含 JGB 方的 上傳的表現嗎」；主會話答 JGB 面板現只送文字、L1～L3 沒有上傳，請業主定「照片和文件上傳要不要列進這次上線範圍」，列「列進去／不列進去」兩選項（未標推薦）；業主回「列進去」。

**為什麼這樣決定**：
- jgb2 面板 `AgentTurnClient.php` 只送 `'arguments' => ['message' => $message]`；只照 L1～L3 上線，面板傳不了照片與文件。
- 接口 A（`docs/api/jgb2-web-assistant-integration.md` §7、§7.1）已有上傳流程與限制，JGB 照做即可，不必另寫規格。

**已知限度**：
- 現行 `_image_recognize_batch` 走 `IMAGE_RECOGNITION_MODEL`（OpenAI，成本記 `openai_cost_tracking`），與 DSP-080「走開源」方向不一致，上線後由 DSP-111 切換片處理。
- 2026-10-17 品質評估是「撇除 圖片」做的；OV 口語題組與 M0 是否含上傳回合未查。

**被否決的替代方案**：
- 不列入、上線後再做：業主選列入。
