# DSP-134：專用對話 API 的契約取捨（入口值、狀態碼、session 位置、跨入口續用）

**日期**：2026-10-31　**決定者**：業主（核可計畫時採入主會話建議，等級 C）

**決定**：
1. 新增 `POST /api/v1/agent/turn`、`POST /api/v1/agent/upload-ticket`（對外經 nginx 為 `{AICHATBOT_BASE}/v1/agent/turn`、`…/upload-ticket`）。用加法：與 `/mcp` 共用同一份工具 registry、同一個 `_invoke`、同一組請求層閘（金鑰 → Origin → `X-JGB-Identity`）；`/mcp` 留到呼叫端改完才關。
2. `Identity.entry` 用新值 `"dialogue"`；後端入口集合 `BACKEND_ENTRIES = {"mcp", "dialogue"}`，判斷一律經 `identity.is_backend_entry()`，⛔ 在 `identity.py` 以外寫 `entry` 字面比較（稽核不變量 28c）。
3. 錯誤以業務代碼回應：非 200 body 為 `{"code", "detail"?}`，狀態碼對照見 `mcp_facade.DIALOGUE_STATUS_BY_CODE`；`AGENT_UNAVAILABLE`、`METERING_UNAVAILABLE` 回 503（確定沒處理），`TOOL_TIMEOUT` 回 504（結果未知，確認回合 ⛔ 自動重送）——這兩條查無業界對應，由第一原理推導。表外代碼與未預期例外一律 500 固定 body。
4. `session_id` 放 `X-JGB-Identity` header，不放網址（偏離 Lex／Bedrock 的路徑寫法）：它是綁 `(user_id, role_id)` 的 128 bit 亂數，放網址會進 nginx access log。
5. 對話鍵與入口無關（`state_store.NAMESPACE = "mcp"`）：同金鑰＋vendor＋`session_id` 換入口可續用同一段對話與確認卡；同一把金鑰兩入口共用每小時上限與額度。
6. 計量分得出入口：新入口 `channel="dialogue_api"`、`processing_path="api:<tool>"`、`answer_source="dialogue_api"`。
7. 入口核心（`_make_invoke`）暫留 `mcp_facade.py`，模組搬家等 `/mcp` 關閉時一起做。

**業主原話**（2026-10-31，回 `plan-dialogue-api-20261031.md` §9）：「核可，§9 照建議 (Recommended)」。

**取捨**：第 4 點代價是從網址看不出 session；第 5 點是刻意的——同一主體換入口不斷線（資安審查 r1 確認不是越權）；第 7 點讓 `mcp_facade.py` 暫時同時裝兩個入口的核心，換來本片不動大檔結構、`/mcp` 回歸風險較小。
