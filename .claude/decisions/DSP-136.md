# DSP-136：修繕單照片現在就走 API 規格 #22（multipart 送 `POST /api/external/v1/repairs`）

**日期**：2026-10-31　**決定者**：業主

**決定**：修繕單照片現在走 API 規格 #22：客人按確認後，由程式以 `multipart/form-data` 把照片位元組送到 JGB 的 `POST /api/external/v1/repairs`（`broken_photos[]`），跟寫入改接片一起上線。取代 DSP-130「上線前 #22 不動；移交片開片時 B、E、#22 三選一」的時點。JGB 工具移交片開片時若要改走 B（JGB MCP server 申請上傳）或 E（multipart 換 `file_id`），要附推翻卡由業主裁。

**業主原話**（2026-10-31，回 `plan-write-wiring-20261031.md` §2 Q2 等待裁題）：「1 好、2a、其餘照建議」＝Q2 照建議走 #22。Q2 建議出自主會話（等級 C）。

**依據**：
- 今天上線只有 #22 做得到：本系統 `create_repair` 已有 `photo_files` 分支（UD-3）；JGB staging `544e8592eb` 的 `RepairController::collectBrokenPhotos` 已收檔（≤10 張、每張 ≤5,000,000 bytes、JPEG／PNG）。B 要 JGB 先有 MCP server，目前沒有。查證：`git -C ~/dev/work/jgb2/dev1 show 544e8592eb:app/Http/Controllers/External/RepairController.php | grep -n collectBrokenPhotos`。
- 偏離：目標正本 §6 原記業主先前選 B（DSP-130，等級 C、選時未查業界做法）。本條是業主知情改選。

**範圍**：只定照片走哪條路與時點。JGB 工具由 JGB 維護、本系統當 MCP client 的目標方向（DSP-130）不變。
