# DSP-121

以下為 2026-10-28 建立時的原文與依據。

**決定**：
- 先把現行程式部署到正式機 `chatai.jgbsmart.com`，讓測試人員在展示團隊驗證；對話模型用 gpt-oss（`openai.gpt-oss-120b-1:0`，Bedrock 東京）。這取代 DSP-080／DSP-087「先跑出數字、定全線門檻才切換」的切換條件；全線門檻改成在測試期間依數字定。
- LINE OA 與站內幫手同一個 `rag-orchestrator` 容器，部署時一起換，業主接受。
- 照片辨識改走 DocuMind（方向）；時機由主會話預設排在上線後（業主未回時機）。DocuMind 現行模型也是 OpenAI `gpt-4o-mini`（DocuMind `backend/app/config.py` `OPENAI_MODEL`），改走不會換掉模型。

**業主原話**（2026-10-28 對話）：「已經拖了很多時間 需要上測試環境能給測試人員驗證」；主會話問 (a) LINE OA 一起換是否接受、(b) 用 gpt-oss 或 gpt-6-luna，業主回「a 別管 line OA」「b 部署用 gpt-oss」；照片辨識業主說「要走 改走 DocuMind」。

**為什麼這樣決定**：
- 能給測試人員的環境只有正式機加展示團隊（站內幫手金鑰 101 限 vendor 4；`deploy-and-online-test-guide-20261015.md` §1）。
- 任務目標是 gpt-oss 替換後的回應品質（目標正本 §0），測試人員要驗的就是 gpt-oss。

**已知限度**：
- 錯筆卡未歸零（DSP-119 片 X8 REFUTED），測試人員與 LINE OA 使用者都可能遇到。
- 正式機金鑰：主會話提出 DSP-090 定本機長期金鑰 ⛔ 用於正式機、短期金鑰＋自動更新未實作；業主回「金鑰 不管」，正式機金鑰由業主處理，本線不實作。

**被否決的替代方案**：
- 先用 gpt-6-luna 部署：業主選 gpt-oss。
- 先跑完數字、定門檻再切換（DSP-080／DSP-087）：業主以時程優先。
