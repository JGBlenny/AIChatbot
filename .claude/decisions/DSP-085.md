# DSP-085

以下為 2026-10-17 建立時的原文與依據。

**決定**：寫入流程由程式掌握。5 支寫入動作（`bill_due_extend`、`repair_create`、`estate_create`、`contract_create`、`manual_bill_create`）共用一張表單；模型每回合在 strict 輸出必填 `write_intent`（動作與使用者原話裡的欄位值）；程式把通過值閘的欄位存成會話草稿 `write_draft`，照表算缺欄、追問，欄位齊了由程式自己發 `confirm.request` 出確認卡。確認卡、雜湊綁卡、兌現流程（DSP-038）不變。

**業主原話**（2026-10-17）：「修繕 不能延續處理了嗎」「像是品質是不參考 要寫規則 這會不會也是類似問題」「但是需要通用處理 不能局部補丁」；三方向中選「程式掌握流程」；審查後選「核可＋授權 commit 第一片」。

- 只加提示詞要求模型每回合呼叫 `confirm.request`：依模型習慣的補丁，換模型要重測（業主「不能局部補丁」）。
- 含網頁按鈕 `action:<name>` 入口：業主未選，暫不做（需 jgb2 前端配合）。
