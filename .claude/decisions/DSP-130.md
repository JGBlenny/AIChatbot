# DSP-130：本系統是對話服務，對話入口與 JGB 工具都要和 MCP 分開

**日期**：2026-10-30　**決定者**：業主

## 決定

本系統是對話服務，不是 MCP 系統。目標架構：

- 呼叫端（一般程式，不是 AI）經專用對話 API 進對話服務，不走 `/mcp`。
- 對話服務含對話入口、AgentRuntime、AI 呼叫、大綱、草稿、確認卡、出口檢查、轉人，以及系統自有工具。
- JGB 工具（`jgb2.*`、`JGBSystemAPI`）不屬於對話服務，由 JGB 維護。連線方向是對話服務當 MCP client；要不要真的走 MCP，移交片實測後確認（見「時機與待裁」）。
- 只有外部 AI 要把本系統當工具呼叫時，才另開 MCP 入口。
- 本機留一層 JGB 工具代理：工具白名單、寫入確認檢查、解碼與投影、依據標記。這層不搬，DSP-091 的程式環節才成立。

圖與現況差距：`.kiro/specs/agentic-mcp-orchestration/architecture-target-20261018.md`「實體架構」節。

業主原話：「你的主體是對話服務 只是 暫時 mcp 坐在內部 要分清楚」「對話服務 跟 mcp 調用 應該分兩個區塊吧 ?」「哪站內幫手就不該從 /mcp 入口進入 因為他使用的是對話服務」「你這個架構沒分開」「且怎麼還是呼叫 /mcp 我說正確的架構 不是現有的」。

修繕單附照片：業主選 B（出自主會話建議，等級 C；業主原話「b 給我完整的正確架構」）。MCP 申請上傳、HTTP 傳檔、MCP 建單，照片本體不走 MCP。選項與依據：MCP 工具參數是 JSON（`mcp` 2.1.1 `CallToolRequestParams.arguments`），現行上限 10 張、每張 5,000,000 bytes 轉 base64 約 67 MB。選 B 時未查業界做法；反向攻擊已查，見下。

## 時機與待裁

本節的「上線前不動」「上線後待裁」與「開片的推翻卡推薦維持現況」已被 DSP-131 取代。

- 照片要重裁：B 的前提是工具走 MCP。上傳單獨走 HTTP 時，E 案（`POST external/v1/uploads` multipart 回 `file_id`，建單帶 `file_ids`，Zendesk 兩步同型）與 API 規格 #22 都不需要申請步驟。B 與 #22 衝突：#22 寫「JGB 不用提供專用上傳網域、簽章網址」。上線前 #22 不動；移交片開片時 B、E、#22 三選一，附推翻卡。
- 連線方式待實測：Intercom、Rasa、Salesforce、Google CES 支援 MCP client，但它們是平台，要接很多系統；本系統只有一個後端，工具又要本機白名單。MCP 對函式的延遲、JGB 維護人力都沒有資料（等級 D）。MCP 與 JGB 維護的 REST 客戶端，實測後由業主確認。
- 目標方向由業主定，等級 C：目前沒有資料證明改了對使用者效果更好（業主選，依據是系統定位，不是量測）。開片的推翻卡 (e) 若仍是「無」，推薦選項是維持現況並取得數據（全域「推翻現況的建議」第 2 條）。
- 上線前不動（DSP-115）：現行 `AgentTurnClient` 是 JGB staging 已接好的 MCP 用戶端，改入口要 JGB 同步改並重驗；本系統也要新做對話入口，命名空間身分、額度計量、金鑰閘、`Identity.entry` 都要處理（`docs/architecture/AGENTIC_MCP_ARCHITECTURE.md` §0「不可複用的」表）。
- 上線後待裁：做的時機、順序，以及 JGB 工具的連線方式。改 MCP 連線的延遲未實測。
- 開片時附推翻卡並經反向攻擊：`/mcp` 成為唯一對話入口是 DSP-046 刪舊 REST 鏈的結果，不是專門裁定；2026-09-04 的 `agent.turn` 進 M1（`design.md` 決策 15）是加入口，沒有規定站內幫手只能走 MCP；DSP-043「LIFF 走 MCP」的對象是 LIFF，要一併處理。
- 本決定不改 DSP-091 分工：唯讀查詢與寫入的下一步由本系統程式決定；寫入確認的檢查從工具層（`_wrap_write_tool`）拆到本機 JGB 工具代理，JGB 不必知道已確認。
- 換入口不會自動得到逐字串流：帶事實的句子要過 Verifier 才能送（`design.md` 決策 15），逐字串流要先做逐句 Verifier。

## 不動

專案與文件名（`agentic-mcp-orchestration`、`AGENTIC_MCP_ARCHITECTURE.md`）不改名，正文寫清定位：`agentic-mcp` 同時是盤查功能鍵，引用處多，改名不影響上線。

## 已知破口

AgentRuntime 直呼 `tools/confirm.py`、`write_candidates.py`、`write_forms.py` 與 `services.jgb` 的函式，並直接 import `tools/jgb2.py` 的語意函式；`confirm.request` 本體與它的下游查 JGB；MCP 門面的 `_open_repairs`、`_repair_category_tree` 與 `action_tools._resolve_category` 也沒有經過 `registry.call`。移交時一起處理。

移交片的前提（反向攻擊 P1 與 P2，`~/jgb-archive/arch-step3-20261018/arch-review-20261030/attack-r1.md`）：本機工具白名單；工具結果語意留本機；身分由程式注入；JGB 支援冪等；上傳票搬到對話 API；測試底座改走同一入口。
