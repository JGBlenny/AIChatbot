# DSP-043

以下為 2026-10-15 整理前 DECISIONS.md 該列「決定」欄原文

**業主 2026-09-08「outcome 採」（先否決三個布林「有點針對客製、應該更通用」）**：`agent.turn` 回應加**第七鍵 `outcome`**＝機器可讀的回合結果，與畫面無關、任何呼叫端共用：`{state, expects, action, ref}`；`state` 封閉八值 answered／clarifying／confirm_pending／confirmed／cancelled／failed／handoff／out_of_scope；`expects` 四值 text／choice／button／none；`action` 為寫入動作名或 null；`ref` 為執行成功的識別碼 `{type: repair|bill|contract, id}` 或 null。值由 Runtime 在各出口**程式**設（確認卡、兌現、取消、失敗、轉人、範圍外、照片終止），一般出口依 `kind`／`quick_replies` 導出；⛔ 不由模型、不由字串判。取代 L15-12 延後的 `scope_exit` 鍵與 LIFF 要的完成訊號。同日一併裁：**LINE 照片緩衝 3 秒**（line-bot 端把同一使用者 3 秒內的照片＋文字合成一回合，⛔ 不拆回合）、**LIFF 走 MCP**（LIFF 前端→line-bot relay→同一把 key 打 `agent.turn`；⛔ 不接舊鏈 REST `/v1/message`，依 R10）。**否決**：`form_triggered`／`form_completed`／`form_cancelled` 三布林（REST 同名，但只服務 LIFF 一種畫面）；LIFF 另開 HTTP 端點。
