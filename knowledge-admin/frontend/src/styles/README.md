# 管理頁樣式架構（2026-09-11 起）

## 為什麼要做

盤查 50 個 `.vue` 檔的實測：

| 指標 | 值 |
|---|---|
| `.vue` 總行數 | 45,530 |
| 其中 `<style>` | 19,512 行（**42%**） |
| 相異色值 | **359 個** |
| `.btn-primary` | 19 個檔、**15 種不同定義** |
| `.badge` | 19 個檔、13 種 |
| `.stat-value` | 16 個檔、14 種 |
| 出現在 ≥3 個檔的類別 | 107 個，合計 559 份定義 |

⇒ 同一個元件在不同頁長得不一樣；改一次按鈕要改十九個地方。

## 現在有什麼

- `tokens.css`——設計 token。⛔ **值全部取自現況最高頻的實際用色／間距，不是重新設計**。
- `components.css`——共用元件樣式。⛔ **每條取自「最多檔案採用」的那個變體**。

匯入順序在 `main.js`：`style.css` → `tokens.css` → `components.css`。

## ⚠️ 為什麼加了共用樣式，畫面卻沒變

單檔 `<style scoped>` 編譯後是 `.btn-primary[data-v-xxx]`，
specificity 高於這裡的裸 `.btn-primary` ⇒ **單檔定義永遠勝出**。

這是刻意的：加入基礎層本身**零視覺風險**。要讓共用定義生效，
必須逐檔刪掉該檔的重複區塊——而那一步**會改變外觀**，
因為該檔原本用的是 15 種變體之一。

## 已完成（外觀零變化，且「零變化」是驗證出來的）

### 第一批：刪等價重複
18 檔、39 個區塊（`.form-group`／`.header-actions`／`.badge-*` 等），刪掉後渲染結果相同。

### 第二批：正規定義改由資料算，各檔只留 delta
⛔ **第一版的 `components.css` 是我手寫的，被數字否決**：`.btn-primary` 的 delta
反而比原本多（72 條 → 118 條），因為我塞了多數檔案根本沒設的屬性，
每個檔都得明示重設。⇒ **正規定義必須是各檔的多數交集，不是理想值。**

改成「某屬性在該類別的所有出現中，≥50%（且至少 3 份）的檔案設同一個值才收進共用層」後：

| 指標 | 收斂前 | 收斂後 |
|---|---|---|
| 單檔 `<style>` 行數 | 19,512 | **18,658** |
| 共用層 | 0 | 285 行（38 個類別） |
| 打包後 CSS | 282,686 bytes | **272,979 bytes**（−3.4%） |
| 被改寫的區塊 | — | 230 個 |

**驗收方式（⛔ 不靠眼睛）**：對每個被改寫的 (檔, 類別)，
比對「共用層 ∪ 該檔 delta」是否**逐宣告等於收斂前**。
結果 **230 組全部等價、0 例外**；未被工具改動的 117 組本來就沒風險。
**正對照**：刻意把共用層的 `.badge { font-size }` 改成錯值，檢查器抓到 13 組
⇒ 這把尺看得見病灶，「0 不等價」可信。

### ⛔ 工具刻意不碰的情形（保守）
`!important`、同屬性重複宣告（順序有意義）、shorthand 與 longhand 並存
（如同時有 `background` 與 `background-color`）⇒ 一律跳過，維持原狀。
共 117 個區塊落在這裡。

## ⛔ 還沒做的，以及為什麼停在這裡

單檔仍有 18,658 行 CSS。剩下的重複**不能再機械收斂**——
它們是真正的分歧（`.btn-secondary` 19 份定義、無任何屬性有多數共識），
統一就是**選定一個外觀並改變十幾個頁面**。那是設計決定。

⚠️ **驗證限制**：build 過 **≠ 外觀正確**。本次的等價檢查能證明
「收斂沒有改變任何宣告」，但⛔ 證明不了「統一變體之後畫面仍可接受」。
要往下走，得先補視覺回歸測試，或由人逐頁驗收。

## 怎麼 build

```
cd knowledge-admin/frontend
docker run --rm -v "$PWD":/app -w /app node:20-alpine \
  sh -c "npm install --no-audit --no-fund && npx vite build"
```
