## 2. 第 1 步「正式接線」的已知事實與未知

### 2.1 程式接點（出處：盤查報告 §B）

- 連線只靠設定：`app.py` 用 `get_llm_provider()`；OpenAI SDK 讀 `OPENAI_BASE_URL`；模型 `AGENT_MODEL`；推理強度 `AGENT_REASONING_EFFORT`（值域含 `low`，以 `extra_body` 送）。
- **會壞的地方**：唯一呼叫點 `AgentRuntime._next_model_message` → 唯一解析點 `_run_model_loop` 的 `json.loads(content)`；content 夾 `<reasoning>`／JSON 前後雜字 ⇒ SCHEMA 改寫至預算用完轉人，且原文（含推理）被 append 進 messages。寫入意圖路徑已由 `write_forms.parse_write_intent_content` 處理。
- 價目表 `usage_metering.DEFAULT_PRICING` 沒有 gpt-oss。
- 截斷：`finish_reason == "length"` 只記 `LLM_OUTPUT_TRUNCATED`，無處置（屬第 3 步）。
- 回歸網：`tests/unit/agent/test_pipeline_golden_req.py`（28 情境逐位鎖住回應形狀）；接線後正式機仍跑 luna，清理邏輯只在回應真有標籤時動作。

### 2.2 業界／官方做法（已渲染，原文在 `~/jgb-archive/devflow-20261018/sources-oss/`）

- OpenAI（gpt-oss 原廠）`openai-cookbook-handle-raw-cot.txt`：「Raw CoT will be returned as part of the response unless reasoning: { exclude: true } is specified as part of the request.」「The raw CoT is exposed as a reasoning property on the message in the output」；推理原文不應給使用者看。
- AWS 三頁（`aws-model-parameters-openai.txt`、`aws-model-card-gpt-oss-120b.txt`、`aws-api-keys.txt`）：未提推理內容如何回傳（搜 `reasoning` 0 命中）；API 金鑰：短期金鑰（≤12 小時或產生它的工作階段，取較短者）建議用於正式環境，長期金鑰只建議探索與開發。
- ⇒ **第 0 步探測**（照 steering 先探測）：數回合確認 Bedrock 是否接受 `reasoning: {exclude: true}`（或回傳 `reasoning` 欄位而非夾在 content）；可行 ⇒ 從源頭關掉，不可行 ⇒ 在 `_next_model_message` 剝除並讓 messages 存清理後內容。

### 2.3 本地測試的安全與前置（新視窗開工前確認）

- **JGB 寫入安全**：常駐服務的 compose 預設 `USE_MOCK_JGB_API=true`、`JGB_API_BASE_URL` 預設 `https://preview.jgbsmart.com`；實際 `.env` 值未查（依規定不讀 `.env`）。⇒ 跑寫入腳本前須業主確認本機 `.env` 為 mock，⛔ 對 preview 真寫。
