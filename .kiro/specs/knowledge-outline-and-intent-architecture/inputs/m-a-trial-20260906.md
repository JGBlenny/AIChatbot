## 4. 預算為什麼破：cache write 不共享

每個判者第一次呼叫都把 ≈60k token 整段寫進快取（`cache_creation`），第二次呼叫才讀；**判者之間沒有共用前綴**（rubric＋39 候選在每個判者都重寫一次）。95 判者 × 60k × $2.5／MTok＝$14.4，佔 91%。這不是 Workflow 腳本能改的（前綴由 harness 子代理系統脈絡＋工具 schema 決定，≈49k）。可行的省法（業主裁）：
1. **候選瘦身**：候選全文 ≈6k token／判者，砍成「標題＋首句」省 ≈10%——但 `evidence_unit`（第幾句）失去依據，⛔ rubric 不改不建議（1.4 §3 已述）。
2. **判者數**：改 1 判者＋抽樣複判，成本減半但一致率量不到。
3. **不用 Workflow 子代理**：直接打 Messages API（system 前綴＝rubric＋候選、可 `cache_control` 共用，每判者只剩 ≈1k 未快取），估 95 判者 ≈$1.5——但失去 harness 的 schema 強制與 journal 續跑，要自建；這是 design 決策 7「Workflow 價值在判者隔離與 schema 強制」的反面代價，量出來了。
4. **預算初值改核**：若接受 Workflow 形式，答案步預算應改為 ≈$20／55 格（含第 3 判者），整案 $25；請業主核。
