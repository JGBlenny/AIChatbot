## 6. 情境式 e2e（第一輪，2026-09-04）——REFUTED，三處結構修正

第一輪 e2e verifier 扮演三種客戶 43 輪／9 session，判 **REFUTED**：單輪成立，多輪被打穿——
- **N-1 根因**：上一輪問句併入檢索 query 撈到相鄰知識（個人房東方案等）⇒ grounding 非空 ⇒ 放行 ⇒ LLM 對本輪問句自由生成（同一句冷 session 固定句、有脈絡就編）。修法：本輪問句**自身**也要過門檻，自身零命中即空。
- **N-2／N-4**：inline 閘門觸發後仍接 `next_question` ⇒ 固定句非逐字、假事實從問句溜出。修法：閘門觸發＝直接回 handoff 決策（只固定句）。
- **新**：事實題被 brain 判 `recommend` 走推薦路徑逃過閘門（「舊系統資料可以匯進來嗎？含房東租客合約帳單」→ 四項全說可匯）。修法：`fact_class≠other` 一律以 answer 處理；所有售前合成加【逐項對照】指令。
修後自測：該題 ×4 全固定句（原 2/3 過度推廣）；600 戶同 session ×3 逐字相同；真推薦題仍推薦。
