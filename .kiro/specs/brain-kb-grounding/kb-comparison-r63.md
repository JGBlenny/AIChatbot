# R6.3 對照留檔：憑印象 vs 查庫（費用/規定類岔題實測）

> 實測日期：2026-07-21｜環境：dev compose（真 LLM＋真檢索 pgvector+reranker＋mock JGB＋vendor_id=1/tenant/b2c）
> 方法：同一修繕面向情境（`trigger_facet_key=repair_create` 進面向後岔題），
> 分別以 `SEARCH_KB_ENABLED=false`（憑印象＝現行行為）與 `true`(查庫＝本案)實跑，答案並列。
> 用途：R6.3 收案證據；B 區價值判定與 A 區（進場路由 agent 化）評估依據。

## 逐題對照

### 1.「這個修理要收費嗎」（費用類）

| | 憑印象（off） | 查庫（on，status=hit） |
|---|---|---|
| 答案 | 關於修理的費用問題，具體情況會依據維修項目和合約內容而定，建議您查看合約或聯繫物業管理了解詳細資訊。 | 根據一般的租賃合約，房東負責房屋的主要結構及設施的修繕，例如水管、電路等問題；而租客則負責日常使用造成的損壞修繕。但具體情況可能因合約而異，建議您確認合約內容或聯繫您的管理師以獲取詳細資訊。 |
| 岔題輪耗時 | 2.06s | 5.31s |

**判讀**：憑印象只能空泛推給合約；查庫給出與 KB id 2968（修繕費用負擔）一致的歸屬劃分（房東＝結構性／租客＝日常損壞），資訊量實質提升、無庫外事實。

### 2.「修理費用是房東出還是我出」（費用歸屬類——幻覺風險題）

| | 憑印象（off） | 查庫（on，status=hit） |
|---|---|---|
| 答案 | **修理費用通常由房東負擔**，但具體情況可能依租約而異。 | 一般來說，房東負責房屋的結構性修繕及設施的維護，例如水管漏水或電力故障等。而租客則需負責因日常使用導致的輕微損壞，例如燈泡更換。具體的負擔劃分可能依合約有所不同，建議您確認租約內容以了解自己的權益。 |
| 岔題輪耗時 | 1.44s | 6.37s |

**判讀**：本案核心價值的直接證據——憑印象**斷言「通常由房東負擔」**，遺漏租客的日常損壞責任，屬過度簡化的歸屬結論（誤導租客的幻覺風險）；查庫答案與 KB id 2968 幾乎逐字一致，歸屬劃分完整正確。

### 3.「師傅大概多久會來」（時程類——庫中無明確時程知識）

| | 憑印象（off） | 查庫（on，status=hit） |
|---|---|---|
| 答案 | 關於修繕的時程，具體的到達時間通常取決於修繕公司的安排，**建議您直接聯繫他們**以獲取更準確的資訊。 | **目前無法確認**師傅大概多久會來，您可以**透過管理師**提交修繕申請，我們會協助您處理相關事宜。 |
| 岔題輪耗時 | 2.11s | 3.78s |

**判讀**：憑印象引導租客「直接聯繫修繕公司」——不符 JGB 流程（租客窗口是管理師）；查庫版誠實承認無法確認時程（R3.2 誠實回退），並依 KB id 2966（修繕通知）引導走管理師，流程正確。

## 彙總

| 指標 | 結果 |
|---|---|
| 工具呼叫率（3 題岔題輪） | 3/3（search_kb_status 皆非 NULL） |
| 命中率 | 3/3 hit |
| 與 KB 內容一致性 | 3/3 一致（#2 幾乎逐字對齊 id 2968；#3 誠實回退＋對齊 id 2966 流程） |
| 憑印象缺陷 | #2 歸屬斷言過度簡化（幻覺風險）、#3 流程引導錯誤、#1 空泛無資訊量 |
| 岔題輪延遲增量 | on 平均 5.15s vs off 平均 1.87s，增量約 +3.3s（樣本 3、dev TestClient 含冷啟；prod P90 以 runbook §14-5 驗收 SQL 為準，目標 ≤3s） |

**結論**：查庫使費用/規定類岔題答案從「空泛或誤導」升級為「知識庫背書、歸屬完整、流程正確」，且庫中無答案時誠實回退不補庫外事實。延遲增量約 3 秒級，接近但可能超出 R5.3 的 ≤3s 目標邊緣，prod 部署後以驗收 SQL 實測 P90 為準；若超標依 design 觸發設計覆核（候選手段：檢索 top_k 降載、工具輪 streaming 提示）。
